Provisions the requested .NET SDK into the shared per-agent cache directory
(~/.cache/jenkins-pipeline/dotnet on unix, %LOCALAPPDATA%\cache\jenkins-pipeline\dotnet
on Windows) and runs the given block with it available on PATH (DOTNET_ROOT is
also set to the cache directory). The environment change only applies for the
duration of the block.

Selector resolution when no version/channel/globalJson argument is given:
a global.json in the workspace root is used if present (its sdk.version's
major.minor is tracked as a floating channel, matching GitHub Actions'
setup-dotnet - bump your global.json to move to a newer SDK); otherwise the
org-wide pinned default version is installed (see Dotnet.DEFAULT_VERSION).

Also idempotently registers the shared "wooga_nuget" NuGet feed into a
workspace-local ./nuget.config (created via `dotnet new nugetconfig` if one
doesn't already exist - a project-level config takes precedence over a
user-level one, so this guarantees the registration actually takes effect)
and binds the 'artifactory_read' Jenkins credential for the duration of the
block, exporting NuGetPackageSourceCredentials_wooga_nuget so `dotnet
restore`/`dotnet test` etc. can authenticate against it with no extra setup -
the credential is never written to nuget.config or any other file. Override
with nugetSourceName/nugetSourceUrl/nugetCredentialsId, or opt out entirely
with nuget: false.

usage: ```
// selector auto-detected (workspace global.json, else org-wide default)
withDotnet {
    sh "dotnet build"
}

// explicit selector (at most one of version / channel / globalJson)
withDotnet(channel: "8.0") {
    sh "dotnet build"
}
withDotnet(version: "8.0.401") {
    sh "dotnet build"
}
withDotnet(globalJson: "${env.WORKSPACE}/global.json") {
    sh "dotnet build"
}

// custom NuGet feed/credentials, or opt out entirely
withDotnet(nugetSourceName: "wooga_nuget", nugetSourceUrl: "https://wooga.jfrog.io/artifactory/api/nuget/v3/wooga_nuget/index.json", nugetCredentialsId: "artifactory_publish") {
    sh "dotnet nuget push out/*.nupkg"
}
withDotnet(nuget: false) {
    sh "dotnet build --no-restore"
}
```

Caveat: a `sh` script with its own login-shell shebang (`#!/bin/bash -l`) re-sources
`/etc/profile` and `~/.bash_profile`/`~/.profile` before running, which on some
agents unconditionally overwrites PATH - discarding the PATH set by withDotnet
before your script's first line even runs. DOTNET_ROOT survives this (generic
profile scripts don't know about it), so if you need a login shell, re-add it
defensively as the first line of your script:

```
withDotnet {
    sh(script: '''#!/bin/bash -l
        export PATH="$DOTNET_ROOT:$PATH"
        dotnet build
    ''')
}
```
