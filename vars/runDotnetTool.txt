Provisions the requested .NET SDK (same as withDotnet: shared cache dir,
wooga_nuget feed, artifactory_read credentials), installs the given NuGet
package as a local (manifest-based) dotnet tool - creating a tool manifest if
one doesn't already exist - then runs it via `dotnet tool run &lt;tool-binary&gt;
-- &lt;args&gt;` with the given args. A "--" separator is always inserted before
the args so dotnet forwards option-like values (e.g. --help) to the tool
instead of intercepting them as its own CLI options. The tool's package cache
is redirected under the shared per-agent cache directory, same as
withDotnetTool.

Map-form-only, unix-only options (ignored on Windows - bat has no shebang,
umask, or `set -x` equivalent):
- loginShell (boolean, default false): run via a `#!/bin/bash -l` shebang
  instead of Jenkins' default `sh -xe`, so the tool sees the same environment
  a login shell would set up (e.g. profile-sourced PATH entries). A login
  shell may re-source /etc/profile / ~/.bash_profile and overwrite PATH,
  discarding the cache dir this library put on it - an
  `export PATH="$DOTNET_ROOT:$PATH"` is automatically re-added right after
  the shebang to defend against that. This replaces Jenkins' default
  invocation entirely, including its default -x tracing - pair with
  logCommandToStdErr to opt back into that.
- umask (string, optional): prepended as `umask &lt;value&gt;` before the
  tool command.
- logCommandToStdErr (boolean, default false): prepends `set -x` (echoes
  each command to stderr before running it) - useful with loginShell since a
  custom shebang loses Jenkins' own default tracing.

Map-form-only, unix/macOS-only options:
- stdoutFile / stderrFile (string, optional, either or both): duplicate that
  stream of the tool into the named workspace-relative file, while the tool's
  output still streams live to the console exactly as it does without them.
  An unrequested stream is left completely alone. Read the file back yourself
  with readFile - the file belongs to you and is deliberately not cleaned up,
  so a post block can still read it after the stage failed, which is the main
  reason to use this over returnStdout. The step's own contract is unchanged:
  a nonzero tool exit still throws unless you also pass returnStatus: true,
  so failing the build stays declarative and only the reporting is yours.
  The files are truncated at the start of the run before anything can exit
  early, so a leftover file from an earlier build on a reused workspace is
  never read back as this run's output - but they may legitimately be empty
  (a tool that writes nothing to that stream, or a run that failed before the
  tool started), so guard with fileExists/a non-empty check rather than
  treating content as guaranteed. No requirement on how the tool splits its
  output: a tool that prints everything to stdout just leaves stderrFile
  empty. Paths are validated, not sanitized - quotes, $, backticks,
  backslashes, newlines, absolute paths, and `..` are rejected with an error,
  since the file has to stay both shell-safe and readable via readFile.
  Naming the same file for both streams is rejected too. Using either on a
  Windows agent is rejected with an error rather than silently producing no
  file for a caller that is about to read one. Also always replaces Jenkins'
  default `sh -xe` invocation with its own script (like loginShell does),
  regardless of whether loginShell is set - so its own default `-x` tracing
  is silently dropped too; pair with logCommandToStdErr: true to get it back
  (that tracing goes to the console, not into the capture files).

usage: ```
// simple form
runDotnetTool("dotnet-ef", "dotnet-ef", ["database", "update"])

// map form - explicit version (passes --allow-downgrade) and returnStatus
runDotnetTool(
    packageId: "dotnet-ef",
    toolBinary: "dotnet-ef",
    args: ["database", "update"],
    version: "8.0.4",
    returnStatus: true
)

// run via a login shell with explicit tracing and a shared-cache-safe umask
runDotnetTool(
    packageId: "dotnet-ef",
    toolBinary: "dotnet-ef",
    args: ["database", "update"],
    loginShell: true,
    logCommandToStdErr: true,
    umask: "002"
)

// capture the tool's stderr to a file, keeping the normal throw-on-failure
// behavior - the post block reports it whether the stage passed or failed
stage("Validate Configs") {
    steps {
        runDotnetTool(
            packageId: "adv5-config-val",
            toolBinary: "adv5-config-val",
            args: ["validate", "configs", "--env", "ci"],
            stderrFile: "validation-stderr.log"
        )
    }
    post {
        always {
            script {
                if (fileExists("validation-stderr.log")) {
                    def findings = readFile(file: "validation-stderr.log", encoding: "UTF-8")
                    if (findings.trim()) {
                        // e.g. forward the findings to Slack; the stage has
                        // already failed on its own if the exit code was nonzero
                    }
                }
            }
        }
    }
}
```
